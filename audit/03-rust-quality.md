## Scope & method

- **Threat model:** this is a single-user desktop app. The adversaries that matter are a compromised webview (it can call any IPC command), a malicious or broken remote host or network, and bad data (an imported DB, a crash mid-write). Most findings here are reliability and correctness problems, not exploitable bugs. Security-specific items are recorded briefly and marked **cross-ref 2A**.
- **Files read in full:** `lib.rs`, `vault.rs`, `vault/credentials.rs` (production part), `vault/ssh_keys.rs` (production part), `scheduler.rs`, `monitoring.rs` (production part), `ssh.rs`, `ssh_pool.rs`, `ssh_exec.rs`, `ssh_tunnel.rs`, `ssh_connect.rs`, `discovery.rs`, `scanner.rs` (production part), `ai.rs`, `launcher.rs`, `db.rs`, all 13 migration files, `docs/SCHEMA.md`, `test_salt_api.rs`, `tests/vault_salt_fix_test.rs`. Relevant parts of `sftp.rs`, `health.rs`, `host_tracker.rs`, `vault/audit.rs` and `tailscale.rs` were read too.
- **Concurrency checks:**
  - Every `.lock()`, `RwLock` and `tokio::sync::Mutex` site, found by grep, was checked for guards held across `.await` and for nested acquisition order.
  - Every `tokio::spawn`, `async_runtime::spawn`, `thread::spawn` and `spawn_blocking` site was inventoried with its stop path.
  - Dependency behaviour was checked in the vendored sources under `~/.cargo/registry/src/*/`: `russh-0.62.7/src/client/mod.rs:1101-1161,1840-1850` for when `connect_stream` returns, and `rusqlite_migration-2.6.0/src/lib.rs:618-651,714-722` for the single-transaction migration path and `DatabaseTooFarAhead`.
- **Error handling:**
  - awk scans of every non-test region (everything before the first `#[cfg(test)]`) for `unwrap`/`expect`/`panic!`/indexing/`as`-casts and for `let _ =` / `.ok()` / `filter_map(|r| r.ok())`.
  - Each hit was triaged by hand.
- **Migrations:**
  - Read every file and the registration in `lib.rs:100-127`.
  - Built the final schema by applying the SQL files to an in-memory SQLite database with Python's `sqlite3`. Nothing was written to disk.
  - Reproduced the migration-014 foreign-key failure the same way (RUST-011).
  - Diffed the result against `docs/SCHEMA.md` and CLAUDE.md.
- **Stray files:**
  - `Cargo.toml` has no `[[bin]]`/`[[test]]` sections, and `build.rs` is `tauri_build::build()` only.
  - `git log` covered `test_salt_api.rs`.
  - grep found no references to it anywhere.

## Proposed module splits (RUST-020)

Tauri command names are the function identifiers, not their paths, so moving commands doesn't change any frontend `invoke()` string. `generate_handler!` already accepts path form (see `ssh::write_ssh` at `lib.rs:1968`).

## Checked and clean

- **EDW-15 fix: verified in code.**
  - Every master-key consumer goes through `credential_access()`: `lib.rs:222`, `:287`, `:998`, `:1267`, `:1294`, `:1310`, `:1351`, and `scheduler.rs:373`.
  - `get_master_key()` has no non-test callers outside `vault.rs` (grep).
  - `delete_credential` takes `credential_gate()` (`lib.rs:1378`).
  - `change_master_password` takes the gate with `write_owned()` at `vault.rs:551`, *before* reading the old key or setting `changing_password` (`:554-577`), and holds it until the new key is installed (`:720-739`). The post-commit/pre-swap window from recon §4.1 is therefore closed for gated callers.
  - Access is dropped before network work: `lib.rs:228`, `:293`, `:1015`, and at the end of `resolve_cred_for_task`.
  - Residual gap: `import_database` (RUST-004).
- **Lock ordering: no inversions found.**
  - Vault: gate → `inner` everywhere, and nothing holds `inner` while acquiring the gate.
  - A `CredentialAccess` holder never re-enters `credential_access()` or awaits anything else that does, so tokio's write-preferring `RwLock` can't self-deadlock.
  - `AlertEngine::evaluate` locks rules → cooldowns → states → active (`monitoring.rs:476-554`); the other methods take one lock each.
  - `claim_scan` locks `stop_signal` → `is_scanning`; the other scanner functions take one lock each.
  - `SshState` locks sessions → `last_activity` only (`lib.rs:1904-1912`); `write_ssh` releases sessions first.
  - `ssh_pool` never nests the map lock and a slot lock: the map is locked briefly, then the slot, then (in the sweep) the map again only after the slot guard is dropped at the end of each iteration.
- **No `std::sync` guard is held across `.await`.** All 60+ `.lock()` sites are block-scoped or temporaries. `Arc<std::sync::Mutex<MetricsCollector>>` is used only from a sync command, so the std mutex is correct there (see RUST-022 for the real issue).
- **Panics in reachable production code: none found.**
  - The only `unwrap`/`expect` calls are on constant regexes (`validation.rs:29,54,82,99`, compile-time-constant patterns covered by tests) and `.expect` on `tauri::Builder::run` (`lib.rs:2033`, standard).
  - Every slice or index is guarded: `crypto.rs:60-63` (AES-GCM output is always ≥ 16 bytes), `scheduler.rs:140-144` (char-boundary truncation), `ssh_auth.rs:42,46` (after `starts_with("~/")`), `ssh_exec.rs:391` (after a `len() >= 2` check).
  - Casts are clamped (`lib.rs:729,934`, `scheduler.rs:512,667`).
  - The exception is the overflow in RUST-015.
- **Migrations:**
  - Ordering in `lib.rs:103-126` matches file order.
  - rusqlite_migration applies all pending migrations in **one transaction** (`goto_up`, `rusqlite_migration-2.6.0/src/lib.rs:618-651`), so a failed upgrade rolls back cleanly.
  - The 011/012 hooks are idempotent (`PRAGMA table_info` check).
  - Destructive steps (005 drops the legacy `credentials`/`credentials_new` after copying `credentials_new`; 009 and 014 rebuild tables) are historical. They preserve data with FKs satisfied, except in the RUST-011 edge case.
  - `SELECT *` in 009 relies on the column order from 005+008, which matches.
  - No migration file has been edited since the repo's first commit; the 011/012 files are comment-only by design.
- **ssh_exec retry safety:** only `ChannelOpen` failures on a *reused* session are retried (`ssh_exec.rs:84-86`, `:229-241`), so a command is never re-sent after delivery.
- **Scheduler overlap between cron ticks:** none. Ticks are serialized (the loop awaits `run_due_tasks`), and within a tick each task appears once. Overlap only comes from the manual-run path (RUST-005).
- **Scanner stop race (Sep 17 fix):** intact. `claim_scan` runs synchronously before `tokio::spawn` (`lib.rs:442-444`), and `ScanRunningGuard` is installed first thing (`scanner.rs:316`).
- **ssh_pool slot pruning:** `Arc::strong_count(slot) == 1` is checked while holding the map lock (`ssh_pool.rs:231-242`), and slot clones are only made under that lock, so a concurrent `acquire` can't be lost.
- **Tailscale CLI:** fixed arguments, `kill_on_drop`, and a timeout (`tailscale.rs:162-174`).
- **Clippy:** `--all-targets -D warnings` was clean at baseline (`raw/cargo-clippy.txt`). None of the post-baseline diffs add `allow`s.
