## Threat model used for severities

A single-user desktop app. The realistic adversaries are (a) a compromised webview (an XSS or a malicious dependency), which can already call any registered IPC command, and (b) a malicious remote host or network peer that controls data the UI renders: SSH output, hostnames, mDNS names, SFTP file names. A bug only counts as a security issue here if it gives one of those adversaries something they couldn't already get, such as a plaintext secret that outlives the vault lock. Otherwise it's rated as correctness, availability or UX. There are no Critical or High findings under this model.

## Scope & method

- **Read in full:** `TerminalComponent`, `RemoteManager`, `SessionContainer`, `SshFileManager`, `MonitoringView`, `AIAssistant`, `NetworkScanner` (listener half), `NetworkTopologyView`, `DashboardView`, `CredentialManager`, `VaultProvider` (listener/lock half), `VaultSettings` (logic), `SettingsView`, `ScheduledTasksView` (logic), `useSshHostKeyVerification`, `useViewVisibility`, `useTailscaleStatus`, `Layout`, `main.tsx`, `SessionToolbar`, `SshHostKeyPrompt`, `KnownHostsManager` (logic), `CredentialSelector` (logic), `SystemHealthWidget`/`AlertFeed` (listener halves), `HostList` (logic), `QuickConnectWidget` (fetch), `HealthCheckBadge`.
- **Effects and cleanup:** grepped every `listen(` (9 files), `setInterval`/`setTimeout`, and xterm/vis-network construction, then read each cleanup path to check whether it unlistens when cleanup runs before `listen()` resolves.
- **Secrets:** grepped `password`, `localStorage`, `sessionStorage` and `console.*` (60 call sites). I traced the SFTP and manual-entry password flow from `CredentialPrompt`/`reveal_credential_password` into React state. I checked that `get_credential` returns `CredentialFrontendView` (`src-tauri/src/lib.rs:1288-1301`), that the view has no password field (`src-tauri/src/vault/credentials.rs:47`), and that `reveal_credential_password` is the only command returning one (`lib.rs:1304-1317`).
- **Rust ↔ TS type contract:** a script pulled every `Serialize` struct's fields from `src-tauri/src` (22 structs). I compared them with the hand-written TS interfaces and counted duplicates with `grep '^interface'`.
- **Dead code:** `npx --yes knip` ran from the npm cache without writing to the repo (`git status` was clean afterwards). It **partially failed** (`Error loading vite.config.ts (Cannot find module 'vite')`, because `node_modules` is absent). Knip counts `*.test.*` files as entries, so components that only their own test imports weren't reported. I closed that gap by grepping importers of every component and hook, excluding tests. Dependency usage was checked the same way, by grepping `src/`, `scripts/` and `postcss.config.js`.
- **Bundle:** `audit/raw/npm-build.txt`. Lazy boundaries were found with `grep React.lazy|Suspense`. `npm view vis-network@10 exports` was used to check the default entry point. Per-library byte sizes weren't measured (no build or visualizer, per the read-only rules).
- **Accessibility:** a Python scan of `<button>` blocks without an accessible name, `<label>` elements without `htmlFor`, and `onClick` on non-interactive elements, plus manual review of all 10 `role="dialog"` components.
- **Not done:** no build, test or runtime execution. No XSS-into-IPC analysis (that's Phase 2B; cross-refs are noted inline).

## Checked and clean

- **`get_credential` carries no secrets.** `lib.rs:1288-1301` returns `CredentialFrontendView::from(...)`, and that struct (`credentials.rs:47`) has `has_password`/`has_private_key`/`has_key_passphrase` and no secret fields. `reveal_credential_password` (`lib.rs:1304-1317`) is the only password-returning command. Frontend callers are `CredentialManager.tsx:601,626` (explicit copy/reveal) and `RemoteManager.tsx:200` (SFTP start) only. The SSH path passes `credentialId` only (`RemoteManager.tsx:210`). The edit form never prefills the password (`CredentialManager.tsx:294,540-541`). The claim is verified; the lifetime issue is FE-001.
- **No secrets are persisted or logged.** `localStorage` only holds `quasar_settings` (notification and appearance flags, `SettingsView.tsx:9-23`). `sessionStorage` only holds `quickConnectHost` (`id/name/address/port/username/protocol`, `DashboardView.tsx:78`). None of the 60 `console.*` calls passes a password or credential variable; they log error objects and fixed strings.
- **xterm lifecycle.** `term.dispose()` also disposes the loaded `FitAddon`. The `onData` disposable, `ResizeObserver` and the fit timer are all released (`TerminalComponent.tsx:211-227`). `disconnect_ssh` is sent on unmount. A disconnect that races an in-flight `connect_ssh` is handled by the backend's pending-connection tombstone (`ssh.rs:161-199,570-600`), and StrictMode doesn't double-connect because the init effect is gated on `isReady` (false at mount). Closing a tab unmounts only that tab (`SessionContainer.tsx:95-113`, `RemoteManager.tsx:329-337`).
- **vis-network lifecycle.** `network.destroy()` runs on every rebuild and on unmount (`NetworkTopologyView.tsx:199-205`). Node `title`s are plain strings, so no HTML tooltip from network-controlled hostnames. XSS depth is 2B.
